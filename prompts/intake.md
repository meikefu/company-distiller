# 需求采集提示词

只询问会改变对象身份、治理规则或执行方式的信息。

1. 目标公司：法定名称、别名、注册号或股票代码、国家/地区，以及稳定的 ASCII `slug`。
2. 对象边界：合并口径公司、法律实体、业务单元、站点、产品、客户账户或竞品集合。
3. 现有状态：新建工作区，或现有规范公司对象的路径。
4. 输入：公开文件、CRM、访谈、合同、客服支持、使用数据或其他结构化来源；同时确认数据所有者与版本。
5. 治理：密级、允许的受众与用途、个人数据处理、保留期限和授权限制。
6. 输出：所需的 `public`、`sales`、`customer-success` 或 `executive` 投影。

默认规则：

- 没有内部数据源时只使用 `public` 策略。
- 仅在不存在法律实体歧义时采用合并口径公司边界。
- 先创建规范工作区，不直接编写公司 Skill。
- 公司名称不含 ASCII 字符时，要求显式提供 ASCII `slug`。
- 不得推定内部数据可以被另一个受众或用途复用。
