# 设计评审

## 结论

Company Distiller 是一个版本化的公司对象系统。生成的 Skill 是面向特定受众和用途、受策略治理的投影；它既不是数据库，也不等于完整的公司对象。

## 保留的设计原则

1. 先建立本体和稳定实体身份，再进行总结。
2. CRM、合同、工单和使用数据必须保留为类型化结构记录。
3. 证据、业务有效期、观察时间、置信度、生命周期和策略都是一等数据。
4. 生成的运行时指令与详细数据分开存放。
5. 使用确定性验收门和真实的多轮运行验证系统。

## 已实施的修正

| 早期倾向 | 已实施修正 |
|---|---|
| 单份 Markdown 公司档案 | 使用仅追加的规范账本和不可变快照 |
| 只有一个公司对象边界 | 拆分为公司、商业关系、产品使用与服务三个领域 |
| 单一 `access_level` 字符串 | 使用可执行的数据分类、受众和用途策略 |
| 只记录 `source_date` | 分别记录业务有效期、事件发生时间、观察时间、摄取或运行时间 |
| 由提示词负责合并 | 通过 `apply_run.py` 的完整预校验与追加写入、基准快照检查和生命周期链接完成 |
| 以 Markdown 为事实来源 | Markdown 改为可重新生成、受治理的 Skill 投影 |
| 只验证目录结构 | 增加 schema、引用、时间、策略、投影、泄露和重放验收门 |
| 自行编写 `PASS` 报告 | 使用包含正向和反向用例的可执行验收套件 |

## 当前参考实现

- `schemas/`：机器契约。
- `scripts/scaffold_company_skill.py`：创建规范工作区。
- `scripts/apply_run.py`：完整预校验后追加增量运行并创建快照；本地多文件写入不是数据库事务。
- `scripts/export_company_skill.py`：生成受治理的 Skill 投影。
- `scripts/validate_company_object.py`：验证规范对象语义。
- `scripts/validate_company_skill.py`：验证投影。
- `scripts/run_acceptance.py`：执行强制发布验收门。
- `example/evolving-company/`：包含三轮运行的内部数据样例。

在线连接器、事务数据库、加密、租户隔离和生产级法定留存执行仍属于部署工作；但它们必须遵守的输出语义，已经由 schema 和离线运行包固定下来。
