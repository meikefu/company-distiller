# 公司本体模型

系统以稳定实体、类型化记录与事件、不可变断言（Claim）、有证据支撑的关系以及受治理的投影为基础。当本文与 `schemas/` 中的机器契约不一致时，以机器契约为准。

## 领域边界

| 领域 | 核心实体 | 状态与证据 |
|---|---|---|
| 公司 | `company`、`legal_entity`、`business_unit`、`site`、`product`、`market`、`risk` | 公开事实、申报文件、产品资料、财务指标、公司事件 |
| 商业关系 | `account`、`person` / `role`、`opportunity`、`contract` | CRM 记录、访谈陈述、合同条款、阶段与签署事件 |
| 产品使用与服务 | `subscription`、`product`、`ticket`、`metric` | 权益、限定范围的使用聚合、工单、事故与服务事件 |

不得把销售方的 `account` 对象等同于目标公司，不得把人员等同于其角色，也不得把合同、实际使用情况和工单互相替代。

## 公司属性

| 一级属性 | 二级属性 | 提取边界 |
|---|---|---|
| 身份 | 法定名称、品牌、别名、股票代码、总部、创始人、法律实体、业务板块、范围 | 合并事实前先解析法律与经营边界 |
| 商业模式 | 价值主张、客户细分、收入来源、定价、渠道、客户关系、成本与利润驱动因素、资源、活动 | 合同和 CRM 观察属于商业关系领域；只有在证据支持归纳时才提升为公司层断言 |
| 产品与服务 | 产品线、SKU、生命周期、目标用户、交付方式、SLA、贡献、依赖 | 区分产品方陈述与已验证的能力或性能 |
| 市场与客户 | 行业、地域、购买角色、TAM/SAM/SOM、成熟度、监管、采用障碍 | 明确记录来源、场景、地域和期间 |
| 财务 | 收入、利润率、现金流、融资、债务、留存、集中度 | 明确期间、币种、会计口径、实体和来源 |
| 组织能力 | 管理层、组织结构、人数、技术栈、销售、支持、交付、供应链、数据 | 招聘信息和个人访谈只是信号，不是直接证明 |
| 战略认知 | 战略判断、增长与壁垒逻辑、资源配置、自建/购买/合作、风险偏好、资本配置、原则 | 需要重复证据或持续行动模式 |
| 竞争 | 竞争者、替代方案、竞争维度、输赢场景、差异化、转换成本 | CRM 输赢记录只适用于其具体商业场景 |
| 生态 | 客户、合作伙伴、供应商、投资者、开发者、渠道、监管者、标准 | 重要连接应建模为关系 |
| 风险 | 财务、法律、合规、安全、隐私、供应链、声誉、执行、技术、宏观 | 区分已披露风险、已观察事件和推断 |
| 时间线 | 发布、收购、管理层变动、事故、监管事件、战略转向、近期更新 | 使用事件和断言有效期，不以纯叙事时间线代替结构化数据 |

## 商业关系属性

| 属性 | 示例 | 边界 |
|---|---|---|
| 客户映射 | 上游 `account` ID、负责人或团队、生命周期状态 | 这是销售方系统的状态，不是客户自我描述 |
| 利益相关者 | 人员令牌、角色、影响力、互动 | 保留同意范围并遵守个人数据策略 |
| 商机 | 阶段历史、金额、预计关闭日期、需求、竞争者、结果 | 观察到的阶段不能证明真实购买意图 |
| 访谈 | 发言人及角色、问题、陈述、时间戳、同意范围 | 陈述必须归因到具体主体，不能写成“公司认为” |
| 合同 | 签约方、版本、生效期、产品、金额、义务、续约与终止 | 只能证明约定，不能证明实际采用或实现价值 |

## 产品使用与服务属性

| 属性 | 示例 | 边界 |
|---|---|---|
| 订阅 | 产品、权益、开始与结束时间、环境 | 与合同和实际使用情况分别建模 |
| 使用情况 | 指标定义、时间窗口、维度、数值、单位、质量 | 高使用量本身不能证明满意度 |
| 支持服务 | 产品及版本、严重程度、状态、时间戳、已验证根因 | 单个工单不能证明系统性缺陷 |
| 健康度 | 重复事故、采用趋势、结果信号 | 派生断言必须显式引用支持证据 |

## 断言模型

每条断言必须包含主体、谓词、类型化取值、断言类型、领域范围、业务有效期、观察时间、证据 ID、审核决定、多维置信度、生命周期链接、治理策略和创建该断言的运行。

断言类型为 `fact`、`metric`、`statement`、`observation`、`inference`、`hypothesis`、`risk`、`obligation` 和 `unknown`。审核决定为 `proposed`、`accepted`、`rejected` 和 `retracted`。

用 `supersedes` 表示纠正或替换，用 `contradicts` 表示尚未解决的互斥观点。不得通过编辑历史记录，把当前事实伪装成始终成立的事实。

## 战略认知判定

一个推断至少满足以下两项，才可提升为战略认知：

1. 在相互独立的来源或行动中重复出现；
2. 能解释过去的产品、市场、招聘、定价、并购或资源配置决策；
3. 能产生可检验的预测；
4. 能把目标公司与相近同行区分开。

必须注明适用边界和未通过的条件。官方叙事只能作为 `statement`，不能视为独立证明。

## 关系模型

关系连接已存在的实体 ID，并记录有效期、观察时间、证据、置信度、治理策略和创建运行。谓词应取自 `schemas/relation.schema.json`。关系不能替代支撑它的记录或事件。
