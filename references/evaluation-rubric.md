# 评估标准

这是一组可执行的发布验收门，不是主观检查清单。运行：

```bash
python3 scripts/run_acceptance.py
```

所有强制验收门都必须通过。警告、占位输出或手工写入的 `PASS` 标签都不能视为通过。

## 强制验收门

| ID | 验收门 | 通过条件 |
|---|---|---|
| G01 | Skill 包 | 根 Skill 通过 `skill-creator` 快速验证，且 `agents/openai.yaml` 与其用途一致 |
| G02 | Schema 覆盖 | 实体、来源、记录、事件、证据、断言、关系、策略、运行、快照、安全溯源与投影的规范 schema 均存在，且能验证代表性数据 |
| G03 | 内部数据保真 | CRM、访谈、合同、支持工单和产品使用数据保持为类型化结构记录，而不是只有叙事文本 |
| G04 | 溯源闭包 | 每条断言和关系都能解析到现有证据；每个证据单元都能解析到投影中的来源、记录或事件溯源；运行与派生链接可解析且无环 |
| G05 | 实体范围 | 每个被引用实体都存在；法律实体、业务单元、人员或角色、产品、客户账户和目标公司可相互区分 |
| G06 | 时间完整性 | 断言包含有效期和观察时间，事件包含发生时间和观察时间；无效区间必须验证失败 |
| G07 | 增量并发 | 三轮有序运行可成功应用；重复的 `run_id` 或过期的 `base_snapshot_id` 必须失败且不得改变账本 |
| G08 | 历史不可变 | 后续运行后，早期行仍逐字节保留；纠正和撤回通过生命周期链接表达 |
| G09 | 变更语义 | 验收样例覆盖 `new`、`reinforced`、`superseded`、`conflicted`、`retracted` 和 `unchanged` |
| G10 | 确定性重放 | 在干净工作区按相同顺序重放同一批运行包，最终快照内容哈希一致 |
| G11 | 策略继承 | 证据、断言和关系不能比依赖项的限制更宽松；策略降级样例必须失败 |
| G12 | 投影隔离 | 面向 `public`、`sales`、`customer-success` 和 `executive` 的 Skill 只包含获授权的断言、证据和安全溯源摘要，不含规范记录或事件的原始载荷 |
| G13 | 示例敏感值隔离 | 不具备权限的受众投影中，不得出现四个固定的 CRM、合同、工单和使用数据测试哨兵；该门禁不替代通用秘密或 PII 扫描 |
| G14 | 严格验证 | 占位符、非法枚举、重复 ID、断裂引用、格式错误的 Markdown 表格和空的伪造包必须失败 |
| G15 | 运行时行为 | 生成的 Skill 包含证据日期、过期规则、事实与推断区分、时间线和真实评估提示词 |
| G16 | 回归套件 | 所有单元与集成测试只依赖已声明的项目或运行时依赖，并全部通过 |

## 质量维度

强制验收门全部通过后，再按以下维度评价质量：

| 维度 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| 证据多样性 | 单一自编来源 | 多种公开或内部来源 | 独立公开来源与运营内部来源并存，且覆盖冲突 |
| 本体实用性 | 通用公司摘要 | 类型化公司与商业关系事实 | 能支撑决策的公司、商业关系和产品使用模型 |
| 更新质量 | 覆盖文件 | 追加运行并生成基础快照 | 支持确定性重放、生命周期传播、审核和回滚 |
| 治理 | 自由文本保密声明 | 可执行的受众策略 | 字段、用途和留存控制由外部安全存储支撑 |
| 评估 | 自编示例答案 | 确定性的结构与行为检查 | 盲测任务集并衡量下游业务结果 |

参考实现通过意味着所有强制验收门均已通过，不代表生产连接器、加密、租户隔离、法定留存控制、通用秘密/PII 扫描或真实场景答案准确性已经获得认证。
